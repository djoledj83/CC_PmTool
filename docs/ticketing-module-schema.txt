This document describes the full data model, API surface, email ingestion,
and UI concepts for an email-driven helpdesk / ticketing module integrated
with the existing Node + Prisma + PostgreSQL stack.

Goals (from product):
  - Listen to a support mailbox; each new email conversation becomes a ticket.
  - Colleagues see an unassigned queue and can assign a ticket to themselves.
  - Replies on the same email thread attach to the same ticket (not new tickets).
  - After assignment, new mail on that thread is tied to the ticket and assignee.

Existing app context:
  - Outbound email only today (backend/src/lib/mailer.js, notify.js).
  - No inbound IMAP/webhook yet — this module adds it.
  - Patterns to mirror: Task, Note, Conversation/Message, Client, Team, RBAC.

Deployment note:
  - This project uses `npx prisma db push` (no migration SQL files).
  - After approving this spec, append the Prisma blocks to schema.prisma and
    run `npx prisma generate` + `npx prisma db push` on Contabo.

2. ENUMS (add to schema.prisma)

enum TicketStatus {
  NEW           // Created from email, never touched
  OPEN          // Someone is working on it (often same as assigned)
  PENDING       // Waiting on customer / third party
  RESOLVED      // Answer sent, awaiting confirmation
  CLOSED        // Done — no further action expected
}

enum TicketPriority {
  LOW
  NORMAL
  HIGH
  URGENT
}

enum TicketMessageDirection {
  INBOUND       // From customer / external sender via email
  OUTBOUND      // Sent to customer from the app (agent reply)
  INTERNAL      // Internal note — never emailed, visible to agents only
}

enum TicketMailboxProtocol {
  IMAP          // Poll inbox (generic)
  MICROSOFT_GRAPH
  GMAIL_API
  WEBHOOK       // SendGrid Inbound Parse, Mailgun, etc.
}

enum TicketIngestStatus {
  PENDING       // Fetched, not yet processed
  PROCESSED     // Linked to ticket / message
  SKIPPED       // Duplicate or ignored (auto-reply, spam rule)
  FAILED        // Parse error — retry or manual review
}

// ---------------------------------------------------------------------------
// TicketMailbox — one configured inbound address (support@, team-a@, …)
// ---------------------------------------------------------------------------
// Admins configure mailboxes. Each mailbox can optionally scope tickets to
// a Team. The ingest worker polls or receives webhooks per mailbox.

model TicketMailbox {
  id              String                @id @default(cuid())
  name            String                // Display name: "Support"
  emailAddress    String                // support@company.com (From on outbound)
  // Optional team scope: tickets from this mailbox default to this team
  teamId          String?
  protocol        TicketMailboxProtocol @default(IMAP)
  enabled         Boolean               @default(true)

  // IMAP (when protocol = IMAP)
  imapHost        String?
  imapPort        Int?
  imapSecure      Boolean               @default(true)
  imapUser        String?
  imapPassword    String?               // Encrypt at rest in app layer / env

  // OAuth / API (when protocol = MICROSOFT_GRAPH | GMAIL_API)
  oauthTenantId   String?
  oauthClientId   String?
  oauthSecretRef  String?               // Or store token JSON encrypted

  // Webhook (when protocol = WEBHOOK)
  webhookSecret String?               // Verify inbound POST signatures

  // Outbound: reuse global SMTP or per-mailbox override
  smtpFromName    String?
  smtpReplyTo     String?               // Optional Reply-To header

  lastSyncAt      DateTime?
  lastSyncError   String?
  syncCursor      String?               // IMAP UID / delta token / history id

  createdById     String
  createdAt       DateTime              @default(now())
  updatedAt       DateTime              @updatedAt

  team            Team?                 @relation(fields: [teamId], references: [id], onDelete: SetNull)
  createdBy       User                  @relation("TicketMailboxCreatedBy", fields: [createdById], references: [id], onDelete: Restrict)

  tickets         Ticket[]
  ingestLogs      TicketIngestLog[]

  @@unique([emailAddress])
  @@index([teamId])
  @@index([enabled])
}

// ---------------------------------------------------------------------------
// Ticket — one support case (email thread anchor)
// ---------------------------------------------------------------------------

model Ticket {
  id              String           @id @default(cuid())
  // Human-readable key for subjects and agent comms: TKT-00042
  number          Int              // Monotonic per workspace; assign in app on create
  mailboxId       String
  status          TicketStatus     @default(NEW)
  priority        TicketPriority   @default(NORMAL)

  subject         String           // Normalized thread subject (no Re:/Fwd:)
  // Requester — external person who emailed in (may not be a User)
  requesterEmail  String
  requesterName   String?

  // Optional link to CRM Client / contact (manual or auto-match by email)
  clientId        String?
  clientContactId String?

  // Assignment — self-service "take ticket"
  assigneeId      String?          // User who owns the ticket
  assignedAt      DateTime?

  // Optional link to internal work
  projectId       String?          // If escalated to a project
  taskId          String?          // If promoted to a task

  // Optional team queue (from mailbox default or manual)
  teamId          String?

  // Threading keys for inbound dedup / reply matching
  rootMessageId   String?          // First Message-ID in thread (RFC 5322)
  // Ticket token embedded in outbound subjects: [TKT-00042]
  publicToken     String           @unique @default(cuid())

  // SLA / housekeeping
  firstResponseAt DateTime?        // First OUTBOUND to customer
  resolvedAt      DateTime?
  closedAt        DateTime?
  closedById      String?

  createdAt       DateTime         @default(now())
  updatedAt       DateTime         @updatedAt

  mailbox         TicketMailbox    @relation(fields: [mailboxId], references: [id], onDelete: Restrict)
  assignee        User?            @relation("TicketAssignee", fields: [assigneeId], references: [id], onDelete: SetNull)
  closedBy        User?            @relation("TicketClosedBy", fields: [closedById], references: [id], onDelete: SetNull)
  client          Client?          @relation(fields: [clientId], references: [id], onDelete: SetNull)
  team            Team?            @relation("TeamTickets", fields: [teamId], references: [id], onDelete: SetNull)
  project         Project?         @relation(fields: [projectId], references: [id], onDelete: SetNull)
  task            Task?            @relation(fields: [taskId], references: [id], onDelete: SetNull)

  messages        TicketMessage[]
  participants    TicketParticipant[]
  tags            TicketTagOnTicket[]
  activityEvents  ActivityEvent[]  // New ActivityEventType values — see §7

  @@unique([number])
  @@index([mailboxId, status])
  @@index([assigneeId, status])
  @@index([teamId, status])
  @@index([requesterEmail])
  @@index([rootMessageId])
  @@index([status, updatedAt])
  @@index([createdAt])
}

// ---------------------------------------------------------------------------
// TicketMessage — one row per email (inbound/outbound) or internal note
// ---------------------------------------------------------------------------

model TicketMessage {
  id              String                 @id @default(cuid())
  ticketId        String
  direction       TicketMessageDirection
  // For INTERNAL notes only — never sent by email
  isInternal      Boolean                @default(false)

  fromEmail       String
  fromName        String?
  toEmails        String[]               // Postgres text[]
  ccEmails        String[]               @default([])

  subject         String?
  bodyText        String?                @db.Text
  bodyHtml        String?                @db.Text

  // RFC 5322 identifiers — critical for threading
  messageId       String?                @unique  // Message-ID header
  inReplyTo       String?                // In-Reply-To
  references      String[]               @default([])  // References header split

  // Who sent from inside the app (null for pure inbound)
  authorId        String?

  sentAt          DateTime               // Date header or receivedAt
  createdAt       DateTime               @default(now())

  ticket          Ticket                 @relation(fields: [ticketId], references: [id], onDelete: Cascade)
  author          User?                  @relation("TicketMessageAuthor", fields: [authorId], references: [id], onDelete: SetNull)

  attachments     TicketMessageAttachment[]
  ingestLog       TicketIngestLog?

  @@index([ticketId, createdAt])
  @@index([inReplyTo])
}

// ---------------------------------------------------------------------------
// TicketIngestLog — one raw fetched email before/after processing
// ---------------------------------------------------------------------------
// Keeps audit trail and prevents double-import. Worker creates row PENDING,
// then PROCESSED with ticketId + messageId or SKIPPED/FAILED.

model TicketIngestLog {
  id              String             @id @default(cuid())
  mailboxId       String
  status          TicketIngestStatus @default(PENDING)

  // Provider-specific dedup key (IMAP UID, Graph message id, webhook id)
  externalUid     String
  messageId       String?            // Parsed Message-ID if present

  ticketId        String?
  ticketMessageId String?            @unique

  fromEmail       String?
  subject         String?
  receivedAt      DateTime?
  error           String?            @db.Text
  rawHeaders      Json?              // Sanitized header map
  // Do not store full raw MIME long-term if size is concern — optional S3 path
  rawStoragePath  String?

  processedAt     DateTime?
  createdAt       DateTime           @default(now())

  mailbox         TicketMailbox      @relation(fields: [mailboxId], references: [id], onDelete: Cascade)
  ticket          Ticket?            @relation(fields: [ticketId], references: [id], onDelete: SetNull)
  ticketMessage   TicketMessage?     @relation(fields: [ticketMessageId], references: [id], onDelete: SetNull)

  @@unique([mailboxId, externalUid])
  @@index([status, createdAt])
  @@index([messageId])
}

10. INBOUND THREAD MATCHING ALGORITHM
================================================================================

When ingest worker receives a new raw email:

Step 1 — Dedup
  If TicketIngestLog exists for (mailboxId, externalUid) → SKIP.
  If Message-ID already in TicketMessage.messageId → SKIP.

Step 2 — Find existing ticket (in order)
  a) Parse In-Reply-To → lookup TicketMessage.messageId → ticketId
  b) Parse References[] (newest first) → same lookup
  c) Subject token: regex \[TKT-(\d+)\] → Ticket.number
  d) Plus-address: ticket+{publicToken}@domain → Ticket.publicToken
  e) Fallback: same mailboxId + normalized subject + requesterEmail within 30 days
     (configurable) — attach to latest OPEN ticket or create new

Step 3 — Create or append
  If ticket found:
    - Create TicketMessage direction=INBOUND
    - If ticket.assigneeId set → notify assignee (TICKET_REPLY_INBOUND)
    - Else → notify team / unassigned queue subscribers
  Else:
    - Allocate Ticket.number, set status=NEW, rootMessageId = Message-ID
    - Create first TicketMessage INBOUND
    - Notify ticket:view_all or team

Step 4 — Auto-reply detection (optional)
  Skip tickets from mailer-daemon, noreply@, Out-of-Office with no In-Reply-To
  → TicketIngestLog status=SKIPPED

11. OUTBOUND REPLY (from app)
================================================================================

When agent posts non-internal message:

  1. Build MIME with:
     - From: mailbox.emailAddress (or SMTP_FROM)
     - To: ticket.requesterEmail (+ original To/Cc if reply-all needed)
     - Subject: "Re: [TKT-00042] {ticket.subject}"
     - In-Reply-To: last inbound Message-ID on ticket
     - References: chain from thread
     - Body: agent HTML/text (sanitized)

  2. sendMail() via existing mailer.js (extend for custom headers Message-ID)

  3. Create TicketMessage direction=OUTBOUND, authorId=agent

  4. Set ticket.firstResponseAt if first outbound

  5. Optionally status → PENDING or OPEN
